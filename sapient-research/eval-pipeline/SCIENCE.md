# Sapient Cognitive Eval — Science Notes

Living document. Each section gets fleshed out as the corresponding code lands. Honest framing throughout.

## 1. What this is

A scoring system for AI agent (prompt, response) pairs on 8 cognitive dimensions, using a brain-encoding model as the judge instead of another LLM. Two tracks:

- **v0** (`SAPIENT_SCORER=v0`, live now) — a deterministic, literature-grounded feature-to-cognitive-dimension scorer. 8 hand-written formulas, each citing a published prior (DuBay 2004, Frith & Frith 2006, Sweller 1988, etc.). Transparent scaffold, not a brain model.
- **v1** (`SAPIENT_SCORER=v1`, in training) — a fine-tuned brain-encoding transformer that predicts BOLD signals across 400 Schaefer parcels, mapped to the same 8 cognitive constructs via a hand-curated parcel-group prior + learned head.

Both run under the same `/api/sapienteval/*` endpoints; the flip is a single env var.

## 2. Architecture (descriptive)

The base model is an 8-layer transformer fusion encoder over text/audio/video features that predicts fMRI BOLD signals (`FmriEncoderModel`). Frozen feature extractors (LLaMA-3.2-3B for text, V-JEPA2 for video, Wav2Vec-BERT for audio) produce per-second embeddings; the trainable fusion encoder consumes them and outputs predicted brain activity. Native output is per-vertex on the fsaverage5 surface (20,484 vertices); we project this to 400 Schaefer parcels at the loss site (see §6).

## 3. Data pipeline

Source dataset: OpenNeuro `ds004996` (NeuroEngage, Torubarova et al., HRI 2025, CC0 license). 50 subjects, 30 with human partners and 20 with Furhat robot partners, ~11 minutes of conversation per run × 3 runs per subject. Pipeline (all on Modal):

1. `data_download.py` (Modal CPU) — pulls BIDS data + the OsLjung annotation repo (real Swedish dialog transcripts) onto the `sapienteval-data` volume.
2. `fmriprep_runner.py` (Modal CPU, `nipreps/fmriprep:24.1.1`) — preprocessing with `--fs-no-reconall --output-spaces MNI152NLin2009cAsym:res-2`. Volumetric only; no FreeSurfer surface reconstruction. **Tradeoff**: skipping `recon-all` removes a credential requirement and saves ~3h/subject of preprocessing time at the cost of slightly less precise lateral cortical alignment — acceptable here because Schaefer-400 is itself a volumetric atlas.
3. `postprocess.py::parcellate_subject` — applies Schaefer-400 7-Networks parcellation via `nilearn.maskers.NiftiLabelsMasker` (z-score + detrend; no bandpass because runs in this dataset are too short for the filter's padlen requirement and the model has its own preprocessing). Output: `(T_run, 400)` float32 `.npy` per run.
4. `postprocess.py::align_subject` — for each TR window, merges (a) per-timestamp participant + operator utterances from the OsLjung annotations with (b) BIDS `event_type` categories (`fixation_cross`, `comprehension`, `production`, `silence`, `turn_initiation`) tagged in angle brackets. HRF shift of 4s applied so each TR's text corresponds to stimuli that drove that BOLD response. Output: `(T_run × text)` JSON per run.

**Honest gap noted**: of the 5 pilot subjects originally selected, `sub-04` had no OsLjung annotation file and was dropped. The pilot trains on `sub-01, sub-02, sub-03, sub-05` — 4 subjects × 3 runs = 12 (text, BOLD_400) training pairs.

**Honest gap noted**: 3 of 5 originally-downloaded BOLD .nii files had NIfTI headers that overstated TR counts (header claimed 573 volumes but only ~400 actually existed on disk). Repaired in-place with `repair_nifti.py` — header dim[4] trimmed to match actual data. fmriprep then ran cleanly.

## 4. The robot-partner training set

NeuroEngage's 20 robot-partner subjects are the closest available analog to "human cognitively processing a non-human conversational interlocutor" — which is structurally what AI agent text is. Training on this data is the central evidence claim of Sapient v1's pitch: the model has been measured against real human neural response to robotic agents.

The pilot's 4 subjects are all human-partner; the robot-partner subjects come in at the 20-subject scale-up. The pre-registered ship gate includes a separate **Spearman R > 0.25 on robot-partner held-out subjects** (`sub-19`, `sub-20`) for the `engagement` construct — see `ACCEPTANCE_CRITERIA.md` §3.

Side-by-side human-partner vs robot-partner per-parcel R will be the headline chart on the v1 model card.

## 5. v0 deterministic scorer

Eight scoring functions, one per cognitive dimension, hand-tuned to give directionally correct outputs on 8 showcase examples (sycophantic, confidently-wrong, refusal-spiral, cognitive-overload, calibrated-uncertainty, tom-aware, tom-blind, computer-use-agent). Each formula carries a citation comment in `src/lib/sapienteval/scorers.ts`. Validated via `scripts/validate-sapienteval.ts` (CLI, no LLM) — currently passes 10/10 brain-only directional invariants.

LLM judge comparison: GPT-4o-mini, structured-output JSON mode, scores the same 8 dimensions on a 0-1 scale. Divergence between brain v0 and judge is the demo's headline — see `src/sapienteval/RadarChart.tsx`. Divergence explanation is a deterministic feature-attribution template (no second LLM call), see `src/lib/sapienteval/divergence.ts`.

## 6. v1 fine-tune — loss computed in 400-parcel space, not native vertex space

We compute the fine-tuning loss in 400-parcel Schaefer space rather than the base model's native 20,484-vertex fsaverage5 surface space. The base model's vertex projection requires a custom MNI-warped mesh artifact (`$FREESURFER_SUBJECTS_DIR/fsaverage5/surf/surf_hybrid_mni_gii/{lh,rh}.{pial,white}.fsaverage5.gii`) we did not have access to. Parcels are a coarser target but appropriate for an N=4 pilot — fewer parameters reduces overfitting risk, and our downstream mapping head operates on parcels anyway. We will revisit surface-space training at the 20-subject scale-up if held-out parcel R warrants it.

Implementation: we feed text-only events through the Sapient data loader (no `Fmri` events, so the surface projector is never invoked at preprocessing time), and inject per-segment parcellated `(B, 400, T_seg)` targets into each batch via `_inject_parcel_targets_into_batch` before the loss is computed. Vertex predictions from the model are projected to parcels via a fixed `(20484, 400)` mean-pool matrix (`_build_parcel_projection_matrix`) at the loss site. MSE loss + 0.1 × temporal smoothness; AdamW with split learning rates (1e-4 for transformer, 1e-3 for readout); cosine schedule with 500-step warmup; 5 epochs; early-stop on within-subject val R plateau (patience=2).

The four sanity checks run before any training spend:

1. **Model instantiates** (`_build_brain_encoding_model` returns without raising, `brain_model.config` accessible).
2. **state_dict diff is zero** — we re-open the raw checkpoint and explicitly compare `set(model.state_dict().keys())` against `set(ckpt.state_dict().keys())` after stripping the Lightning `model.` prefix. Any missing or unexpected key aborts.
3. **Forward + backward on one (text, BOLD_400) pair** — single batch through the full path; loss must be finite.
4. **Gradient isolation** — every frozen parameter must have `grad is None` (or all-zero), every unfrozen parameter must have a finite non-None grad. Any violation aborts.

If any check fails the run aborts and reports which one and why. No silent failures.

## 7. Mapping head (400 parcels → 8 cognitive dimensions)

Not yet implemented. Per the plan, two-step: literature-prior parcel weights (DMN → engagement, TPJ → theory-of-mind, DLPFC/MFG → cognitive load, ACC → frustration/surprise, etc.) combined with a `(400, 8)` weight matrix `W` fit on the NeuroEngage engagement labels via `BCE` on the engagement column + L2-toward-prior on the other 7. Output: `cognitive_scores = sigmoid(bold_400 @ W + b)`.

## 8. Validation methodology

Pre-registered splits live in `splits.json`, stratified by partner group (human/robot) to preserve the 30:20 dataset ratio across train/val/test. The held-out test set (`sub-17..20`) is touched exactly once. Ship gates in `ACCEPTANCE_CRITERIA.md`.

Within-subject val for early stopping = each train subject's `run-03` (held out before training). Across-subject val for model selection = `sub-15` + `sub-16`. Held-out test = `sub-17..20`. The pilot operates only on train; the val + test sets engage at the 20-subject scale-up.

## 9. Known limitations

- N=4 for the pilot is a pipeline-validation run, not a publication-grade model. The robot-partner generalization claim cannot be demonstrated at this scale; that requires the scale-up.
- 1 of 4 pilot subjects (`sub-03`) has very short BOLD runs (21-131 MiB vs 296-407 MiB for the others) — fewer TRs per training pair from that subject. We did not exclude it; this surface-level dataset variation is part of what we want the model to robustly fit.
- Schaefer-400 7-Networks parcels mix neighboring functional subregions; the MFG and TPJ parcel sets we use are approximations derived from label-string matching against the nilearn atlas, not anatomically curated. (2026-08-25 update: the buy-moment detector's analogous `ROI_GROUPS` bundles were checked against real connectivity data and the atlas's own Yeo-7 labels — see `SCIENCE.md` §12 and `scripts/buy_moment/connectome_validation.py`. That check has NOT been run against these mapping-head MFG/TPJ sets specifically; the caveat here stands until it is.)
- All transcripts are Swedish (the source dataset's language). The base text encoder (LLaMA-3.2-3B) is multilingual, but its Swedish coverage is weaker than English. The cognitive eval API will be invoked on English text — this is a real distribution gap and a known limitation of the v1 pilot. The 20-subject scale-up should include validation on translated transcripts before claiming English generalization.

## 11. Buy-moment scoring-layer hardening (2026-08-25)

A literature-gap pass on `scripts/buy_moment/buy_moment_detector.py` (post-processing over parcel activations; no change to the base model, `05_finetune_sapient.py`, or anything under `sapient-models/`). Three changes, real-data-validated where feasible and synthetic-validated with explicit disclosure otherwise.

**11a. Real-behavior validation gate (real citation, synthetic validation).** arXiv:2607.01400 shows a TRIBE-style encoder's aggregate engagement/drive signal does not correlate with real behavior (YouTube replay heatmaps; pooled partial r = +0.058, p = 0.23) despite good held-out fMRI Pearson r — verified via WebFetch of the paper's abstract/results before citing. `buy_moment_detector.py`'s composite score is structurally the same move (weighted sum over parcels → one number), and `ACCEPTANCE_CRITERIA.md` previously gated only on fMRI/Spearman R against neural-derived labels, never a real behavioral outcome for this composite. Checked whether `03_parcellate.py` / `04_align_stimuli.py` emit any real behavioral ground truth distinct from BOLD itself: **they do not** — `04_align_stimuli.py` aligns transcript text and BIDS event-type tags, not a scalar engagement/purchase outcome. New ship gate 4 in `ACCEPTANCE_CRITERIA.md` documents this and requires a real correlation before any behavioral claim ships from a composite like this one. In the interim, `scripts/buy_moment/validate_against_behavior.py` — **synthetic data, explicitly disclosed** — injects a known engagement process into synthetic (T,400) parcel data, runs the real detector on it, and permutation-tests (1000 circular time-shifts) whether `score_z` recovers it above chance. Result: observed r ≈ +0.997, permutation p ≈ 0.001, PASS. **Honest gap noted**: this only shows the detector's arithmetic isn't broken on a favorable synthetic case built to look like engagement — it is not evidence the composite tracks real human behavior, and does not itself satisfy the new ship gate.

**11b. Generalizable vs idiosyncratic channels (real citations, real effect sizes, applied to existing weights).** Genevsky & Knutson (2018, "Neuroforecasting Aggregate Choice"; 2025, "Neuroforecasting reveals generalizable components of choice," PNAS Nexus 4(2):pgaf029 — both fetched and confirmed via WebFetch before citing) show NAcc/ventral-striatal anticipatory-affect activity generalizes across people to aggregate choice (ICC 0.408-0.441, p ≤ 0.009 across two independent experiments) while mPFC integrative-value activity does not (ICC 0.198-0.273, p ≥ 0.08, non-significant). `ROI_GROUPS` in `buy_moment_detector.py` now tags each group `"channel": "generalizable" | "idiosyncratic" | "unclassified"` — the OFC (NAcc proxy) and temporal-pole (amygdala proxy) groups as generalizable, the vmPFC/mPFC and DLPFC groups as idiosyncratic, and the negative/suppressive groups as unclassified (the Genevsky/Knutson dichotomy concerns positive anticipatory-affect vs integrative-value signals specifically, not suppression). `detect_buy_moments` now additionally returns `generalizable_score` and `idiosyncratic_score` (z-scored sums restricted to each channel) plus a `channel_config` dict, alongside the unchanged original `score_raw`/`score_z`/`group_means`/`buy_moments` — purely additive, verified no existing caller reads a narrower shape (grepped the repo; `detect_buy_moments` has no other Python/TS importers today — `src/lib/buyMomentMath.ts` is an independent parallel TS implementation, not a caller of this module). **Honest gap noted**: the temporal-pole → generalizable and DLPFC → idiosyncratic tags are extrapolations from the OFC/mPFC findings specifically (Genevsky & Knutson tested NAcc and mPFC, not temporal pole or DLPFC directly) — documented as such in the ROI_GROUPS rationale strings, not presented as separately measured ICC values.

**11c. CPM-style connectivity fingerprint (real methodology citations, synthetic validation, not wired into scoring).** Finn et al. 2015 (Nat Neurosci, connectome fingerprinting) and Shen et al. 2017 (Nat Protoc, CPM) motivate edge-level functional connectivity as often more behaviorally informative than regional activation amplitude — the only signal `buy_moment_detector.py` currently uses. New `scripts/buy_moment/connectivity_features.py::rolling_connectivity_fingerprint` computes rolling-window parcel-by-parcel Pearson correlation restricted to the existing `ROI_GROUPS` parcel indices (not all 400×400 pairs — unnecessary and slow), plus `mean_between_group_connectivity` for a compact scalar per window. Synthetic validation: injected a known covariance (target r = 0.70) between two ROI groups' synthetic time series, confirmed recovery (observed 0.688, within tolerance ±0.12) alongside a negative-control group pair with no injected signal (recovered ≈ -0.002). **Honest gap noted, explicit in the module docstring**: this feature is NOT wired into the main `detect_buy_moments` composite, and has NOT been validated against any real behavioral outcome — only that the correlation arithmetic is correct on synthetic data. Real-outcome validation is future work, contingent on the same real-behavioral-channel gap noted in 11a.

**What was and wasn't pulled from real sources this pass**: arXiv:2607.01400 and both Genevsky & Knutson papers were fetched and their claims (effect sizes, p-values, ICC values) confirmed via WebFetch before being cited above and in code comments — not fabricated from memory. Finn et al. 2015 and Shen et al. 2017 are cited from established prior knowledge of these standard, widely-cited CPM methodology papers (Nat Neurosci 2015, Nat Protoc 2017) but were not independently re-fetched this session; if precision on their exact wording matters for a future manuscript, re-verify before quoting. No raw OpenNeuro/HCP/DANDI data was downloaded this session (out of scope per the task's ground rules) — all new validation in 11a and 11c is synthetic-only, disclosed inline in both the code and this document.

## 12. Real-connectome grounding of `ROI_GROUPS` (2026-08-26)

Phase 1 (§11) validated the buy-moment *scoring logic* against citations and synthetic data. This pass instead grounds the *parcel-bundle choices themselves* (`ROI_GROUPS` in `buy_moment_detector.py`) — the thing §9's "not anatomically curated" limitation flags — using real connectome data where feasible, plus a broader connectome-predicts-behavior literature pass. New module: `scripts/buy_moment/connectome_validation.py`.

**12a. Real-data internal-connectivity check (real data, real computation).** Pulled real, public, no-DUA human fMRI via `nilearn.datasets.fetch_development_fmri` — the Richardson lab "development dataset" (OpenNeuro `ds000228`; naturalistic Pixar-short movie-watching, not resting-state or an ad, but a closer task analog to Sapient's video-viewing use case than rest). Fetched up to 40 subjects' worth of metadata to find those flagged `Child_Adult == 'adult'`: 9 adults found, 8 successfully extracted (1 subject, `sub-pixar124`, dropped — zero-variance parcel produced a divide-by-zero in the correlation and was excluded rather than silently kept). For each of the 8, extracted Schaefer-400 parcel time series via `NiftiLabelsMasker` (detrend, z-score, 0.01-0.1 Hz band-pass, confound regression, TR=2.0s), computed each subject's (400, 400) Pearson connectivity matrix, and averaged across subjects. For every `ROI_GROUPS` bundle, compared its mean within-group pairwise connectivity against a null of 1000 random same-size parcel draws from all 400 parcels.

Result (real numbers, `n_subjects_used=8`, `n_null_draws=1000`, full JSON in `scripts/buy_moment/connectome_validation_out/connectome_validation.json`):

| Group | observed within-group r | null mean r | percentile vs random |
|---|---|---|---|
| Limbic_OFC | +0.319 | +0.093 | 100th |
| Default_PFC_vmPFC | +0.259 | +0.092 | 100th |
| Default_Temp_SocCog | +0.223 | +0.093 | 100th |
| Limbic_TempPole | +0.266 | +0.091 | 100th |
| Cont_PFCl_DLPFC | +0.232 | +0.092 | 100th |
| SalVentAttn_FrOperIns | +0.379 | +0.093 | 100th |
| Cont_Par_CogLoad | +0.332 | +0.092 | 100th |
| SalVentAttn_ParOper | +0.397 | +0.092 | 100th |

All 8 groups beat all 1000 random draws. **Honest framing**: this shows every `ROI_GROUPS` bundle is measurably more internally coherent as a real functional-connectivity unit than a same-size random parcel set drawn from the same 400 parcels — i.e. the label-string matching did not accidentally bundle functionally unrelated parcels together. It is a necessary-but-not-sufficient precondition for treating each group as one meaningful channel, and it says nothing about whether the group's activity predicts buying behavior specifically — that claim is untouched by this check and remains gated by §11a's real-behavior gate. n=8 adult subjects from one naturalistic-viewing dataset is a real but modest sample; this is not a claim of a definitively "correct" or optimal grouping, only that it clears the "not incoherent noise" bar.

**Confound not yet controlled for, flagged on review**: the random-draw null pools all 400 parcels uniformly, so part of each group's edge over the null is expected purely from **spatial autocorrelation** — nearby parcels on the cortical surface are known to show inflated functional connectivity regardless of functional network identity (a Schaefer parcel is small; several `ROI_GROUPS` entries, e.g. `Limbic_OFC`, `Cont_Par_CogLoad`, sit in tight anatomical clusters). This check does not yet distinguish "coherent because functionally related" from "coherent because physically adjacent." A stronger version of 12a would redraw the null from spatially-matched parcels (same inter-parcel geodesic/Euclidean distance distribution as the real group, e.g. via a spin-test / Moran spectral null) rather than uniformly at random. Until that's run, treat 12a as evidence against *gross* mislabeling (the groups are not incoherent noise) rather than evidence the grouping is functionally, not just spatially, specific.

**12b. Yeo-7 structural consistency (real published labels, no new computation).** Cross-tabbed each `ROI_GROUPS` bundle's parcels against the Schaefer-2018 atlas's own published Yeo-7 canonical network assignment (Schaefer et al. 2018, *Cerebral Cortex*, "Local-Global Parcellation of the Human Cerebral Cortex..." — the same atlas nilearn ships and this codebase already uses; fetched via `nilearn.datasets.fetch_atlas_schaefer_2018`). All 8 groups are 100% pure — every parcel in `Limbic_OFC` and `Limbic_TempPole` is Yeo-7 "Limbic"; `Default_PFC_vmPFC` and `Default_Temp_SocCog` are entirely "Default"; `Cont_PFCl_DLPFC` and `Cont_Par_CogLoad` are entirely "Cont"; `SalVentAttn_FrOperIns` and `SalVentAttn_ParOper` are entirely "SalVentAttn". **Honest framing**: this is a structural label cross-tab against real published atlas data, not an independent connectivity measurement — reported separately from 12a per the task's disclosure requirement, and it only tells us the groups don't straddle canonical networks; it says nothing about functional coherence within that network (12a covers that) or about behavior (untouched).

**12c. CPM published predictive-network masks — located but not parsed this session (honest gap).** Searched for Rosenberg et al. 2016 (*Nat Neurosci*, sustained-attention CPM) and Shen et al. 2017 (*Nat Protoc*, CPM methodology) supplementary network masks via WebSearch/WebFetch. Confirmed via WebFetch of `github.com/monicadrosenberg/Rosenberg_PNAS2020` that a real, public repository exists containing `saCPM.mat` — the actual high-attention/low-attention 268×268 edge masks, in Shen-268 parcellation space, associated with the follow-up 2020 PNAS paper reusing the 2016 CPM. **What we did NOT do**: parse the `.mat` file or verify its internal network-level composition in this session — the repo's README does not itself document which functional networks (frontoparietal, DMN, motor, visual, etc.) the positive/negative networks draw from, and translating a Shen-268 mask to our Schaefer-400 space would require a documented cross-parcellation mapping we don't have. Per the task's own fallback instruction for this exact situation, we drop the quantitative edge-overlap check and instead give the literature-only synthesis below, clearly labeled as such — no specific network-composition claim about the Rosenberg masks is made here beyond what is confirmed in 12d.

**12d. General "connectome predicts behavior" literature (real citations, verified via WebSearch/WebFetch this session; literature-only, no new computation).** Broader justification for connectome-level (not just single-region-amplitude) analysis as the right defensibility layer for Sapient's approach, separate from the narrow neuroeconomics citations already in `ROI_GROUPS`:

- **Finn et al. 2015** (*Nat Neurosci* 18:1664-1671, "Functional connectome fingerprinting: identifying individuals using patterns of brain connectivity") — confirmed via WebSearch (title, journal, volume/page, and abstract-level claims cross-checked across the PubMed listing and a secondary summary, since the Nature and PubMed pages themselves sat behind a cookie/auth wall this session). Individual functional-connectivity profiles, derived from Human Connectome Project data, act as a stable "fingerprint" that identifies a person across scan sessions and even across task vs. rest conditions; connectivity profiles also predict fluid intelligence, with the frontoparietal network the most individually distinctive. This is the primary citation motivating "read out the connectome, not just regional amplitude" as a design principle.
- **Rosenberg et al. 2016** (*Nat Neurosci*, "A neuromarker of sustained attention from whole-brain functional connectivity") — confirmed via WebSearch (PubMed listing + independent secondary summaries); introduces a whole-brain connectivity-based predictive model (CPM) that predicts adults' sustained-attention performance and children's ADHD symptoms from connectivity alone. Cited here as the canonical demonstration that a connectome-level (not single-ROI) model generalizes to out-of-sample behavioral prediction — directly relevant to why Sapient should eventually validate `ROI_GROUPS`-level connectivity against real behavioral outcomes, not just amplitude. Its specific positive/negative network composition is NOT claimed here (see 12c's honest gap).
- **Gordon, Laumann et al. 2017** (*Neuron* 95(4):791-807, "Precision Functional Mapping of Individual Human Brains") — confirmed via WebSearch (title, journal, volume/pages, and result summary cross-checked across independent listings). Using ~5 hours of resting-state fMRI per subject in 10 adults, found that individual brain networks vary anatomically in ways group-averaged atlases obscure — network "pieces" shift location across people even after cortical-surface coregistration. Cited here NOT as support for the current group-atlas approach but as the caveat on it: precision individual mapping is the direction future work (including a possible per-user `ROI_GROUPS` calibration) should eventually move toward, since a single fixed Schaefer-400 grouping is, by this paper's own evidence, an approximation of any specific individual's real network topology.
- An HCP-based individual-differences citation was not independently added beyond Finn et al. 2015 above, which itself uses HCP data for the fingerprinting/fluid-intelligence result — no additional HCP paper's specific claims were verified this session, so none beyond Finn 2015 is cited.

**Framing**: 12a and 12b are about whether Sapient's specific `ROI_GROUPS` bundles cohere as connectivity/network units (they do, by both measures tried). 12d is the general case for connectome-level analysis as a research direction, independent of whether any specific bundle here is optimal — it does not, on its own, validate `ROI_GROUPS`. None of 12a/12b/12d license a claim that `ROI_GROUPS` scores predict buying behavior; that remains gated by the real-behavior-channel requirement in §11a and `ACCEPTANCE_CRITERIA.md` gate 4.

## 13. Real-behavior validation gate — re-checked against actual data (2026-08-26)

§11a's "no real behavioral channel exists in the pipeline" claim was re-checked this pass by pulling the *actual* `ds004996` (NeuroEngage) `participants.tsv` and `participants.json` from `github.com/OpenNeuroDatasets/ds004996` (fetched live via `curl`, not from memory) rather than re-reasoning only from `03_parcellate.py` / `04_align_stimuli.py`'s code, which is all §11a checked.

**What we found, real data**: `participants.tsv` DOES carry per-run columns not previously noticed — `eng_level_run-1`, `eng_level_run-2`, `eng_level_run-3` — each valued `high` / `medium` / `low`, documented in `participants.json` as "engagement level for the \[Nth\] conversation," explicitly mapped to the paper's EC (high, "Engaged Conversation"), AL (medium), and PL (low, likely "Poor Listening"/passive-listening) conditions from Torubarova et al. 2025. This is a genuine correction to the prior "checked, none exists" framing — a real, distinct-from-BOLD label does exist at the participant/run level.

**Why it still doesn't clear gate 4, honestly assessed**: two separate problems, both disclosed rather than glossed over.

1. **It's a condition label, not a measured behavioral outcome.** Per `eng_level`'s own `participants.json` description and the dataset's own README (fetched live, `raw.githubusercontent.com/OpenNeuroDatasets/ds004996/main/README`), these levels correspond to experimenter-designed conversation conditions (the script/manipulation the confederate or robot operator followed), not a participant self-report or independently measured behavioral outcome. It is closer in kind to `04_align_stimuli.py`'s existing `event_type` tags (`fixation_cross`/`comprehension`/etc.) than to a scalar purchase-decision or satisfaction rating — it tells you what condition a run was assigned to, not what the participant actually felt or did. The README's own text on this point: *"Preprocessed data and questionnaire results: to be uploaded"* — i.e. the dataset's authors themselves flag that the genuine self-report questionnaire data (which would be the real behavioral outcome measure) is **not yet in the public release**. This is a real, verifiable, still-open gap in the source data itself, not a gap in our pipeline's use of it.

2. **We have no real parcellated BOLD to correlate it against even if it counted.** `03_parcellate.py`'s output for the phase-1 pilot's 4 subjects lives only on the Modal `sapienteval-data` / derivative volumes from that run (confirmed: this worktree has no local `.npy` parcel files under `sapienteval/data/`, and re-deriving them requires re-downloading raw ds004996 imaging data and re-running fMRIPrep on Modal — multi-hour GPU/CPU compute, out of scope for this session per the task's own stated fallback for "size" or "compute" barriers).

**Other candidates checked and ruled out this session** (WebSearch/WebFetch, not from memory):
- **StudyForrest** — has real, verified continuous affect/arousal annotations paired with naturalistic movie-watching fMRI (Forrest Gump). A genuine behavioral-outcome-bearing dataset in principle. Not pursued further this session: the continuous emotion ratings in the published StudyForrest emotion-annotation extension are collected from separate raters watching outside the scanner, not the same subjects who were scanned, and — same as ds004996 — no parcellated BOLD for any StudyForrest subject exists in this repo or on our Modal volumes; standing it up would mean a fresh download + parcellation pipeline, the same multi-hour compute barrier as above.

## 15. Statistical-methodology hardening (2026-08-26)

**Framing correction, stated explicitly per this session's own instruction**: this system is **not an EEG-fMRI fusion pipeline**. What DOES genuinely apply, because this system actually has: (a) an fMRI-derived `(T, 400)` parcel timeseries (§3-4, §12), (b) hand-picked `ROI_GROUPS` weights that were never statistically fit (buy_moment_detector.py), (c) a connectivity-fingerprint feature (§11c, `connectivity_features.py`), (d) 8 independent hypothesis tests already run with no multiple-comparisons correction (§12a, `connectome_validation.py`), and (e) group-level statistics computed by naively averaging across 8 subjects before nulling (a pseudo-replication risk, flagged but not fixed in §12a). **15a. Multiple-comparisons correction on the 8 ROI-group connectome tests (real data, real computation).** `connectome_validation.py`'s `real_data_internal_connectivity` (§12a) ran 8 independent permutation-style null comparisons with no correction. This pass adds two corrections, both computed on the SAME real 8-subject `fetch_development_fmri` data and the SAME 1000-draw null already described in §12a, reported ADDITIVELY (the original uncorrected `empirical_percentile_vs_random`/`p_uncorrected` fields are unchanged):
- **Benjamini-Hochberg FDR** (Benjamini & Hochberg 1995, *J. R. Statist. Soc. B* 57(1):289-300 — verified via WebSearch this session: title, journal, volume, pages).
- **Max-statistic family-wise permutation correction** (Nichols & Holmes 2002, "Nonparametric permutation tests for functional neuroimaging: a primer with examples," *Hum Brain Mapp* 15(1):1-25, DOI 10.1002/hbm.1058 — verified via WebSearch this session: title, journal, volume, pages, DOI). Implementation: at each of the 1000 permutation draws, take the max within-group connectivity value across all 8 groups to build one pooled family-wise null distribution, then test each group's observed value against that single corrected null.

**Result (real, `n_subjects_used=8`, re-run this session, full JSON in `connectome_validation_out/connectome_validation.json`)**: all 8 groups remain significant after BOTH corrections — every FDR q-value and FWER-corrected p-value is ≤ 0.002 (uncorrected p was already 0.001 for every group, the floor at 1000 permutations). **Honest framing**: the correction changes nothing about which groups pass here because the effect was already maximal at the uncorrected level (every group beat all 1000 null draws, percentile 1.000) — this is a case where the correction is genuinely inert, not a case where we ran it and it happened to not matter for a weaker effect. The correction is still reported because omitting it, even when it doesn't change the verdict, was the actual gap: prior to this pass there was no way to know from the output alone whether 8 simultaneous tests had been accounted for.

**15b. Pseudo-replication fix: subject-level connectivity test (real data, real computation, new).** §12a's `real_data_internal_connectivity` averaged all 8 subjects' `(400,400)` connectivity matrices into ONE matrix before comparing to the null — treating 8 subjects as a single data point, inflating apparent significance and discarding between-subject variance. This pass adds a corrected check, `subject_level_connectivity`, computed on the SAME 8 real subjects: for each `ROI_GROUPS` bundle, each subject's own within-group connectivity is nulled against ITS OWN 200 random-parcel draws (not the pooled matrix), producing 8 independent null-normalized z-scores per group. A Wilcoxon signed-rank test (non-parametric, appropriate at n=8, no normality assumption) then asks whether those 8 per-subject effects are systematically greater than zero.

**Result (real, n=8 subjects per group)**: every one of the 8 `ROI_GROUPS` bundles clears the subject-level test — Wilcoxon one-sided p = 0.0039-0.0078 per group, and all 8 remain significant after BH-FDR correction across the 8 tests (q ≤ 0.0078). Per-subject null-z means range +4.7 to +9.8 (SDs 1.3-3.4) — i.e. the effect is not just present in the pooled average, it is present and fairly consistent in every one of the 8 individual subjects. This is the stronger, subject-respecting result; the original §12a pooled-average numbers are kept in the output (labeled `approach: "pooled_average (pseudo-replicated...)"`) for continuity, but the subject-level check is the one that should be cited for any claim resting on "is this true across subjects."

We additionally computed an **empirical-Bayes shrinkage** of each group's 8 per-subject z-scores toward the population mean (`stat_utils.py::eb_shrink_subject_effects`) — see 15e below for why this specific technique and its provenance. Because the between-subject variance in these z-scores is large relative to the (proxy) within-subject noise term here, the shrinkage factor is close to 1.0 for all 8 groups (little pooling applied) — reported in the JSON per group, not repeated here since it does not change the qualitative picture (all 8 groups pass either way).

**15c. CCA/PLS small-N stability literature (verified via WebSearch this session, not from memory).** Before implementing any multivariate fusion method, we searched for and verified recent literature on CCA/PLS instability in brain-behavior studies at small sample sizes, per this session's explicit instruction:
- **Helmer et al. (2024)**, "On the stability of canonical correlation analysis and partial least squares with application to brain-behavior associations," *Communications Biology* 7:1223 — confirmed via WebSearch (title, journal, article number). Central finding: CCA/PLS brain-behavior weight patterns (both magnitude AND which features/regions load onto the association) are highly unstable at sample sizes typical of neuroimaging studies, and require roughly N > ~1000 subjects to stabilize, extending the Marek et al. Sapient trains on **N=4 subjects (pilot) to N=8 (scale-up target)** — three orders of magnitude below the stability regime this literature describes. **Decision**: per the task's option (a), we implement PLS/CCA anyway (new `scripts/buy_moment/multivariate_fusion.py`) but wrap every fitted number in an explicit instability disclosure, a block-bootstrap stability check, and an MDES abstention gate (15d), rather than either silently treating the fit as validated or skipping multivariate fusion altogether. ## 16. Cultural-calibration magnitude re-check (2026-08-25): direction strengthened, magnitude still unfit

The user directly asked us to find real data to fit `cultural_calibration.py`'s placeholder `_MULTIPLIER_STRENGTH = 0.15` against, replacing it with a literature-derived number if one exists. This section documents what was actually found this session, in full — including the honest negative on the part that matters most (the magnitude).

**Re-read Han & Ma (2014) in full (the paywall is resolved).** §14's original text said the ALE effect-size tables sat behind a paywall and only the qualitative region list had been verified. This session fetched the author-hosted PDF mirror (mylab.bnu.edu.cn) in full via WebFetch and read Tables 2, 3, and 4 directly. They report exactly what a coordinate-based Activation Likelihood Estimation (ALE) meta-analysis reports: cluster weighted-center MNI coordinates and cluster volume (mm³) — **no Cohen's d, Hedges' g, t-value, or any other standardized effect size for any region**. This is not a paywall artifact or an oversight in the paper; ALE is fundamentally a spatial-convergence method (it answers "do foci from independent studies cluster in the same place more than chance," not "how large is the group difference at that place"), so no quantitative multiplier was ever going to be extractable from this specific paper. We also re-searched for a 2023-2026 replacement meta-analysis with an extractable effect size for this exact contrast (vMPFC self-referential / dMPFC-TPJ social-cognition, East Asian vs. Western) and found none — adjacent recent work exists (a 2023 ALE meta-analysis on cultural differences in *inhibitory control*, 2024-2025 self-referential-encoding meta-analyses in unrelated education/development contexts) but nothing on this specific contrast with a reportable number.

**Found a real primary study with actual effect sizes, per the task's fallback instruction.** Ma, Y., Bang, D., Wang, C., Allen, M., Frith, C., Roepstorff, A., & Han, S. (2014), "Sociocultural patterning of neural activity during self-reflection," *Social Cognitive and Affective Neuroscience* 9(1):73-80 (PMC3871729; full text confirmed via WebFetch this session, not from memory). 30 Chinese and 30 Danish participants judged physical/mental/social attributes of themselves vs. a public figure. Reported ANOVA statistics convert to Cohen's d by the standard textbook formula for two independent groups with 1 numerator df (t = √F; d = t·√(1/n₁+1/n₂), n₁=n₂=30 here):

| Contrast | Reported statistic | Converted Cohen's d | Direction |
|---|---|---|---|
| mPFC, self-reflection | F(1,58) = 17.011, p < 0.001 | ≈ **1.07** (large) | Danish (Western) > Chinese — matches Han & Ma's vMPFC finding |
| Left TPJ, social attributes | F(1,58) = 9.308, p = 0.003 | ≈ **0.79** (large) | Chinese (East Asian) > Danish — matches Han & Ma's TPJ finding |
| Right TPJ, social attributes | F(1,58) = 8.979, p = 0.004 | ≈ **0.77** (large) | Chinese (East Asian) > Danish — matches Han & Ma's TPJ finding |

These are real, large, direction-confirming effect sizes from an independent 60-subject study — meaningfully stronger evidence for the **direction** of the calibration than the ALE coordinate tables alone provided.

**Why this still can't replace the +/-15% magnitude, shown rather than asserted.** The d-values above are standardized mean differences computed on that one study's own SPM GLM parameter-estimate scale — an arbitrary-origin, arbitrary-unit beta weight specific to their task design and scanner. `cultural_calibration.py`'s multiplier is applied to `buy_moment_detector.py`'s Schaefer-parcel group-mean activation series, a different measurement with no shared unit. Cohen's d is deliberately unit-free so it can be compared *across* studies that don't share units — which is exactly the property that prevents reusing it as a same-unit multiplier *here*. Bridging the two would require inventing an unstated conversion assumption (e.g., "one SD of their GLM beta ≈ some percent of our parcel-mean amplitude"), which is precisely the kind of unlicensed fabrication this file's disclosure discipline exists to prevent. We looked for, and did not find, any principled way to make that bridge — so we did not build one.

**Net result**: `_MULTIPLIER_STRENGTH` in `cultural_calibration.py` is unchanged at 0.15, still an arbitrary placeholder, still flagged as such everywhere it surfaces (module docstring, `CALIBRATION_TARGETS` sources, the `disclosure` field in `apply_cultural_calibration`'s return value, and `ACCEPTANCE_CRITERIA.md`). What changed is confidence in the **direction** (now backed by a meta-analysis AND an independent large-d primary study, rather than the meta-analysis alone) — not the magnitude, which remains exactly as unfit as it was before this session. `_run_robustness_check()` was re-run after these docstring/source changes and still passes (arithmetic untouched — only citations and disclosure text changed); see `ACCEPTANCE_CRITERIA.md`'s cultural-calibration section for the updated summary and validator run log.

- **Real per-subject film onset/offset**: each subject's `sub-{ID}_ses-{N}_task-scan_acq-BigBuckBunny_events.tsv` gives the real `rest`/`film`/`rest` boundaries (e.g. sub-S01: film onset 93.84s, duration 490.01s) — used directly rather than assumed, and confirmed to vary slightly per subject.
- **Schaefer-400 extraction**: identical method to `connectome_validation.py` — `nilearn.datasets.fetch_atlas_schaefer_2018` + `nilearn.maskers.NiftiLabelsMasker` (standardize + detrend; no additional confound regression since WM/CSF/motion are already regressed per the dataset's own preprocessing).

**Analysis (new module `scripts/buy_moment/real_behavior_emofilm.py`, additive, does not modify `buy_moment_detector.py` or `detect_buy_moments`'s existing behavior)**: for each of 3 subjects, parcel activations were cropped to the real film segment, resampled from TR=1.3s to 1 Hz (linear interpolation) to match the annotation's native sampling, run through the unmodified `detect_buy_moments`, and correlated (`score_z`, `generalizable_score`, `idiosyncratic_score`) against a real engagement proxy (mean of the `IntenseEmotion`/`Alert`/`Attention` annotation columns, z-scored) with a 4-second HRF lag — the same lag convention `SCIENCE.md` §3 step 4 already uses for the NeuroEngage pipeline, applied here rather than re-deriving a new one. Significance was assessed via a subject-blocked circular time-shift permutation null (2000 permutations: each subject's ground-truth block circularly shifted independently, then re-concatenated) — the same style of autocorrelation-respecting null `validate_against_behavior.py` already uses for its synthetic case, extended here to the multi-subject pooled case.

**Result (real, n=3 subjects, 1 stimulus, full JSON in `scripts/buy_moment/real_behavior_out/emofilm_bigbuckbunny_result.json`)**:

| Channel | pooled r | p (block-permutation, two-sided) |
|---|---|---|
| `score_z` (composite) | +0.029 | 0.660 |
| `generalizable_score` | +0.079 | 0.284 |
| `idiosyncratic_score` | +0.107 | 0.077 |

None of the three channels reach significance at α=0.05 pooled across subjects. Per-subject, `idiosyncratic_score` was nominally significant uncorrected in 1 of 3 subjects (S03: r=+0.209, p=0.039) but this does not survive correcting for the 9 comparisons (3 channels × 3 subjects) actually run in this session, and `idiosyncratic_score` is explicitly not the channel an aggregate-level ship claim should be checked against per §"Generalizable vs idiosyncratic channels" above.

**Honest framing.** This is gate 4's first real (not synthetic) correlation number, obtained from real fMRI and a real, continuously-sampled, human-coded engagement annotation, with a permutation null appropriate to the autocorrelation in both series. The result is a real, small, null finding — not a pass, not evidence the composite is behaviorally validated, and not proof the composite could never work either. It is directionally consistent with the exact concern arXiv:2607.01400 raises (an aggregated parcel-group readout does not automatically track real behavior) rather than a refutation of it. The sample is small and narrow in a specific, disclosed way: n=3 of the ~30 subjects Emo-FilM actually has available, 1 of its 14 movie stimuli, and that one stimulus (a children's animated short) is a naturalistic-viewing engagement analog, not a purchase/ad-relevant stimulus — the exact match to Sapient's actual use case this gate ultimately cares about. A more decisive resolution (a confident PASS or FAIL) would extend this same script to more subjects and more of Emo-FilM's movies, and ideally replicate in a second real dataset per the "one dataset's worth of evidence" caveat already used elsewhere in this document's disclosure discipline.

**What was and wasn't verified this pass**: dataset sizes, file existence, annotation schemas, and per-subject session/onset metadata were all fetched live (OpenNeuro GraphQL API, GitHub API, direct S3 `HEAD`/`GET` requests) — not assumed from the accession numbers alone. The absence of FSL/ANTs in this environment was checked directly (`which`, `python3 -c "import nipype"`), not assumed. No raw data beyond the ~1.9 GB of Emo-FilM BOLD + ~4.4 MB of Emo-FilM annotations was downloaded this session; StudyForrest's ~65 MB/run BOLD files and its annotation repository were inspected for size/format but not bulk-downloaded once the registration blocker was identified, per the task's own time-boxing instruction not to attempt a doomed download.
